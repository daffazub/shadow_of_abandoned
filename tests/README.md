# Headless story regression tests

From the project root, with the existing dependencies installed and Node 24:

```sh
npm test
```

Run the monster suite explicitly:

```sh
node --test --test-reporter=spec tests/monster-integration.mjs
```

Run only the corridor suite:

```sh
node --test --test-reporter=spec tests/corridor-areas.mjs
```

Or run every regression file, including corridor geometry:

```sh
node --test --test-reporter=spec tests/player-regression.mjs tests/environment-startup.mjs tests/story-progression.mjs tests/corridor-areas.mjs tests/monster-integration.mjs
```

No ESM loader flags are needed: Node 24 detects ESM syntax in the imported source `.js` files despite the package lacking `type: module`. A module-type warning may appear.

The story harness uses the actual `SceneManager`, `EnvironmentManager`, and `InteractionManager` prototypes, actual `EventSystem` and `MonsterManager` constructors, Babylon `NullEngine`, real meshes/materials/lights, and the story-area overlay/fallback builder. It runs the actual scene loading, door interaction/animation observers, progression, single-monster pursuit, and cleanup implementations. Other constructors with browser listeners or legacy asset preloads are bypassed and their state is initialized by the fixture. Environment startup tests use the actual `EnvironmentManager` constructor.

The unchanged `Game` class is read from `src/main.js` and evaluated in a VM without imports or browser startup. Its real event listeners, A/C ending methods, B final sequence/completion, and document open/close handlers are exercised; only the five-second completion timer is queued manually. The test fails explicitly if the class/bootstrap extraction boundaries change.

Browser canvas/text operations (`OffscreenCanvas` and the DOM canvas used by `DynamicTexture`), minimal overlay DOM, and audio are stubbed. The DOM fixture models `dataset`, child/parent relationships, append/remove, and directly dispatched events. It parses only the document-close span needed by Game, not arbitrary HTML, and does not emulate event bubbling. Story tests stub prop attachment/preload. Prop-specific tests use the real `PropLibrary` and real in-memory Babylon `AssetContainer` cloning; only `LoadAssetContainerAsync` is mocked. Story tests instantiate the real `MonsterManager` and mock `LoadAssetContainerAsync` with an in-memory container. Scenes must start before pursuit; document/light/delta tests place the loaded monster in `chasing` state to isolate those integration conditions. Spawn, normalization, animation, fallback, collision, and late-load lifecycle behavior remain covered by `monster-integration.mjs` with real manager logic and mocked container IO. There is no separate Environment ghost loader or AI. Unexpected `fetch` or unmocked `SceneLoader.ImportMeshAsync` calls throw. The story suite's synchronous import rejection exercises the actual story fallback; it does not replace the scene loader implementation. Scene transitions retain their real 450/250 ms timers. No files are generated by the test.

`npm test` runs all five regression files:

- `player-regression.mjs`: paused battery consumption, long/negative frame deltas, blocked footsteps, and unchanged horizontal normalized WASD movement.
- `environment-startup.mjs`: environment construction before the camera, optional pursuit delegation without a monster/camera, camera replacement/removal, local particle emission bounds, and exponential-squared fog.
- `story-progression.mjs`: the story, interaction, material, timer, and single-monster runtime integration coverage below. Documents assert that pointer lock is released so the close control can be clicked.
- `corridor-areas.mjs`: imported corridor transforms, actual GLB geometry, overlay/fallback behavior, reachability, and cleanup.
- `monster-integration.mjs`: single cached preload, dormant/pending/spawning/chasing lifecycle, light protection, capture, pause/freeze, authoritative floor-helper rejection, floor/wall-aware movement and spawn, stuck recovery, stale async loads, normalization, real animation pause/resume, fallback/disposal, debug/ending guards, background-load ownership races, and delegated pursuit on the actual corridor GLB in both story areas.

`corridor-areas.mjs` adds both synthetic imported-hierarchy tests and an actual local `public/assets/models/corridor_baru.glb` import for each story area. It uses Babylon's real GLTF loader with `skipMaterials` and an in-memory `data:base64,` URL, so no textures, browser image decoding, network, or server are required. It bypasses browser-facing system constructors and stubs ancillary interaction/audio/lighting services; `SceneManager` loading, placement, interactable creation, geometry picking, and cleanup remain real. Loader mocks, plugin observers, canvas globals, scenes, and engines are restored/disposed after each test.

Corridor coverage:

- Shared `STORY_AREA_LAYOUT` and `STORY_CORRIDOR_TRANSFORM` exports; exact player, battery, note/desk-axis, generator, switch, door, and safe-zone placements for the shorter corridor.
- Default procedural fallback dimensions: 3.1 m wide, 15 m long, floor surface y=0, ceiling clearance 4.15 m. Successful corridor imports retain signs/markers only, without procedural floors, walls, partitions, tubes, or machines; overlays do not collide.
- Original `horror_scene_glb` loader behavior: root position reset to zero and root scale reset to one, conversion quaternion preserved, and no story wrapper. Story placement adds only rotation Y=-PI/2 and translation (-5.225,-2.52,5). Sampled world vertices obey `(x,y,z) -> (-z-5.225,y-2.52,x+5)` and keep their distances; child scale/hierarchy stays unchanged.
- Synchronous loader throws and asynchronous rejections produce the story fallback without also constructing the original horror fallback. The original horror environment still invokes its fallback on either failure.
- Actual GLB geometry supplies the floor under starts, safe zones, objectives, and both 3.1 x 4.15 doors at z=12.6. Source-mesh ray checks leave three central torso-height routes open through the progression threshold. Closed door anchors block the route; disabling their collisions permits crossing. This tests reachability along sampled rays, not full swept player-ellipsoid navigation.
- Scene clear disposes imported meshes, overlays, interactable anchors, and the rigid wrapper, and resets tracked safe zones/observers.
- `monster-integration.mjs` additionally imports the actual transformed corridor for both story areas with real SceneManager/EnvironmentManager pursuit delegation. Default spawn distances and the actual floor helper produce a floor-supported spawn; initial safe light hides the monster, the freeze phase completes, source side walls block body rays, and a chase in the unlit gap advances toward the player without leaving the corridor or losing floor support. Scene clear despawns but retains monster geometry for reuse.
- Ownership race: a delayed monster preload resolves while the actual corridor import is held pending. Explicit environment ownership excludes monster meshes from scene cleanup. Clearing disposes corridor/scene objects but preserves monster roots, fit/pivot nodes, materials, and animations; loading the lab reuses the same container/pivot with no second model load. A rejected result from an existing floor helper is authoritative; geometric floor fallback is tested only when that helper is absent.

Story coverage:

- Restricted wing -> lab: closed/open door, width/crossing threshold, control lock, transition re-entry, player reset, actual lab loading, and preserved inventory/documents.
- Ending A: raw progression requests must be one-shot across repeated frames. This deliberately does not install Game's terminal-state listener, which could mask duplicate emissions by locking controls.
- Ending B: actual switch payload/visual state, both event names, control lock, one-shot sequence, and one completion event.
- Single-authority runtime: Environment's `startEntityPursuit`/`stopEntityPursuit` wrappers call the actual monster's `startChase`/`despawn`, restarts reuse one container, and only the corridor uses `ImportMeshAsync` (no second ghost import). Game's real door listener reaches that same manager. Environment has no `updatePursuit` or `ensureEntityModel`; Game's real systems loop updates the monster exactly once, with its exact delta argument checked after normalizing the VM-created argument array to the test realm. Environment disposal leaves monster/asset disposal to the app.
- Ending C: real Monster -> Game document-resume capture and terminal guards. Long/negative/nonfinite deltas and exposure-without-proximity remain asserted here. Flashlight switch/battery/intensity, safe-zone hiding/recovery, eight-second darkness/proximity and wall-aware capture, one-shot ending requests, and player reset/freeze are covered by `monster-integration.mjs`. The removed legacy Environment whisper/repulsion behavior is not part of the single Monster AI.
- `clearScene`: tracked geometry/observer removal, pursuit shutdown, interaction reset, and inventory/document identity and contents preservation. Babylon's deferred observer removal is allowed to settle before inspecting its observer list.
- Actual Game A/C terminal guards: one ending overlay/event, `dataset.ending`, document removal, locked controls, pursuit shutdown, and no subsequent ending/sequence/document replacement. A pending B sequence also ignores ending requests until completion.
- Game documents: actual note event opens the overlay and freezes near-capture pursuit/interaction in the unlit generator area at z=8.5, before power restoration; close button, backdrop, and X restore controls and allow C capture. Closing a document cannot release a transition/final-sequence/game-ended lock.
- Props: off-origin source geometry beneath a vertex-less conversion root with reflected Z, vertex-only cached bounds, material light cap 10, original 3.1 x 4.15 gate rotated PI/2 and equally sized story gate without rotation, actual fitted dimensions/base/center, and top filler geometry. Pickup and scene clear dispose owned placeholders/visuals but preserve shared model materials and permit cached reuse.
- Story timers: real key/generator callbacks fire once and release handles; `game_ended` cancels both pending callbacks and prevents future scheduling. Actual Game `startFinalSequence` stops story/light timers before its separately queued B completion.
- Light timers: `stopLightTimers`, `clearLights`, and `dispose` cancel pending timeouts/intervals. Lab power restoration is idempotent, adds a protective radius-2.5 generator safe zone at (-0.75,0,8.5), hides the monster and stops its movement while reducing exposure, ramps to 0.6 intensity, and emits one completion. These tests use Node's mock timeout/interval clock, not wall-clock waits.
- Model normalization/fallback migrated to `monster-integration.mjs`: preserved reflected/quaternion conversion hierarchy, refreshed off-origin vertex bounds, configured monster height/floor/centering, animation lifecycle, and owned fallback geometry obeying the same light/capture rules. There are no remaining `ensureEntityModel` tests or claims for the old separate 1.9 m ghost.

Scope: these are headless logic/geometry/material-lifetime regressions, not browser, rendering, text appearance, GLB material appearance, CSS, full collision-navigation, or visual validation. The corridor suite imports the actual corridor asset without materials and samples floor/route geometry; prop fitting still uses synthetic gate proportions to exercise the top-panel fitting branch. These tests do not exercise legacy `LevelBuilder` construction/disposal. Manual browser checks are still required for rendered monster visibility/animation/materials, flashlight/safe-light appearance, audio timing, pointer-lock interaction, and end-to-end traversal/ending presentation. Headless fixtures load the actual corridor GLB but use in-memory monster containers (or intentional load rejection), not the actual monster GLB. Actual-corridor pursuit checks sample a spawn and a short chase; they do not prove full-route monster navigation. A failing regression is left failing rather than modifying production code or marking it TODO.
